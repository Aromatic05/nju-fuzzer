## 4. 风险与已知差距（不阻塞运行）

- exec-logs 小文件增长：`ProcessExecutor` 每次执行会写 `stdout_<id>.log/stderr_<id>.log` 到 `tmp/exec-logs/`，长跑可能写爆 inode/磁盘。
- CLI 解析器简化：`CliParser` 按 `key value` 成对解析，不支持复杂 GNU flag 语法。
- 稳定性确认与初始校准开销：在 `shmex` 与 CoverageDB 可用场景下会增加执行次数；若追求吞吐，可提供进一步阈值/开关。

## 5. 补充增量：Crash 判定口径可配置 + 超详尽产物说明

背景：解析器类目标（如 xmllint）常用非 0 exit code 表达“输入非法”，若直接用 `exitCode != 0 => crash` 会造成 crash 风暴；同时在手动停止 fuzz（Ctrl-C）时会出现 `exit_130` 被误记为 crash 的统计污染。

### 5.1 CrashOracle：把“exit code 非 0”和“真正 crash”解耦

- 新增 `CrashOracle` 作为 crash 判定入口：timeout 不算 crash；仅当 `Termination.ERROR` 且 exit code 不在白名单时才算 crash。
- 默认白名单包含 `130/143`，避免 Ctrl-C / SIGTERM 污染。
- CLI 新增 `--nonCrashExitCodes`，支持把指定 exit code（逗号或空格分隔）加入白名单。
- 可观测性：启动时打印最终生效集合 `effectiveNonCrashExitCodes`（默认 + 用户配置）。
